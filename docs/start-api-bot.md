# เริ่มใช้งาน BKK Active CLI ผ่าน API

คู่มือนี้สำหรับผู้ที่มี `session.json` แล้ว รันคำสั่งจากโฟลเดอร์โปรเจกต์
ไม่ต้องเปิด emulator ขณะใช้บอต API
หากยังไม่มี session ให้ทำตาม [ตั้งค่า emulator จากศูนย์](setup-rooted-emulator.md)
และ [เก็บ session](renew-api-session.md) ก่อน

## เตรียมก่อนรันครั้งแรก

ต้องมี Python 3 และอินเทอร์เน็ต หากยังไม่มี `.venv-api` ให้สร้างด้วย:

```sh
sh tools/setup_api_capture.sh
```

สคริปต์นี้ติดตั้งเครื่องมือ capture ด้วย หากเคยทำขั้นตอนเก็บ session บนเครื่องนี้แล้ว
ใช้ `.venv-api` เดิมได้ ไม่ต้องติดตั้งซ้ำ
ตรวจว่า CLI เปิดได้โดยยังไม่ส่งคำขอจอง:

```sh
.venv-api/bin/python open_booking_api.py --help
```

วาง `session.json` ที่ root ของโปรเจกต์ หรือเปลี่ยน `--session` ให้ตรงกับ path ที่เก็บ
ไฟล์นี้เป็นข้อมูลรับรองของบัญชี ห้ามแชร์หรือ commit

## ตั้งเวลาจองทุกวันตอน 07:00

คำสั่งสำหรับ macOS:

```sh
caffeinate -i .venv-api/bin/python open_booking_api.py \
  --session session.json \
  --center "ศูนย์กีฬาเบญจกิติ" \
  --schedule 07:00 \
  --booking-day tomorrow \
  --start-time 18:00 \
  --end-time 20:00 \
  --book \
  --allow-paid
```

บอตรอทำงานทุกวันเวลา **07:00 ตามเวลาไทย (Asia/Bangkok)**
แต่ละรอบค้นหาช่องจองของ **วันพรุ่งนี้เมื่อเทียบกับวันที่รันรอบนั้น** ภายใน 18:00–20:00
ถ้าเริ่มโปรแกรมหลัง 07:00 จะรอ 07:00 ของวันถัดไป ไม่ได้รันทันที

เปิด terminal และเครื่องไว้พร้อมอินเทอร์เน็ต กด **Ctrl+C** เมื่อต้องการหยุด scheduler
`caffeinate -i` ช่วยกัน idle sleep ระหว่างโปรแกรมทำงานบน macOS
ไม่ได้รับประกันการทำงานเมื่อปิดฝาเครื่องหรือสั่ง sleep เอง
บนระบบอื่นให้ตัด `caffeinate -i` ออก และจัดการไม่ให้เครื่อง sleep ตามระบบนั้น

## จองทันทีหนึ่งรอบ

ตัวอย่างตามคำสั่งที่ใช้ Python ของเครื่อง:

```sh
python3 open_booking_api.py \
  --session session.json \
  --center "ศูนย์กีฬาเบญจกิติ" \
  --booking-day tomorrow \
  --start-time 19:00 \
  --end-time 21:00 \
  --book \
  --allow-paid
```

คำสั่งนี้ค้นหาและจองของพรุ่งนี้ภายใน 19:00–21:00 แล้วจบ ไม่มีการตั้งเวลารอบถัดไป
หากต้องการใช้ Python ตัวเดียวกับขั้นเตรียมเครื่อง ให้เปลี่ยน `python3`
เป็น `.venv-api/bin/python` ได้

## ความหมายของตัวเลือก

| ตัวเลือก | การทำงาน |
| --- | --- |
| `--session session.json` | อ่านข้อมูลบัญชีจากไฟล์ session |
| `--center "ศูนย์กีฬาเบญจกิติ"` | ศูนย์ที่ต้องการค้นหา |
| `--schedule 07:00` | รันทุกวันเวลา 07:00 ตามเวลาไทย; ไม่ใส่คือรันทันทีหนึ่งรอบ |
| `--booking-day tomorrow` | จองพรุ่งนี้; ใช้ `today` สำหรับวันนี้ หรือ `both` เพื่อลองวันนี้ก่อนแล้วพรุ่งนี้เมื่อวันนี้ไม่มีช่องว่าง |
| `--start-time` / `--end-time` | เลือกช่องที่เริ่มและจบภายในกรอบนี้ ต้องระบุทั้งคู่และเวลาเริ่มต้องก่อนเวลาจบ |
| `--book` | ส่งจองจริงและส่งรีวิวตามข้อมูลใน session; หากไม่ใส่จะเป็น preview |
| `--allow-paid` | อนุญาตการจองที่มีค่าบริการด้วย บอตไม่ชำระเงินให้ ต้องชำระเองภายหลัง |

**ทั้งสองตัวอย่างส่งจองจริง และยอมรับรายการที่มีค่าบริการ**
บอตเลือกเพียง **1 ช่องตามช่วงที่ API กำหนด** ไม่ได้จองเต็มกรอบเวลา 2 ชั่วโมง
หากต้องการจองเฉพาะรายการฟรี ให้เอา `--allow-paid` ออก

หากต้องการดูก่อน ให้เอา `--book` ออก และเอา `--schedule` ออกเพื่อดูผลทันที
preview ไม่ส่งจอง แต่ผลว่างที่เห็นไม่ได้รับประกันว่าจะยังว่างตอนจองจริง

## ดูผลและใช้งานครั้งถัดไป

แต่ละรอบเก็บผลใน `logger/<รอบรัน>/`:

- `run.log` — สถานะการทำงานและข้อผิดพลาด
- `summary.json` — ผลของรอบรัน
- `api.jsonl` — request/response ดิบ มี token และข้อมูลส่วนตัว ห้ามแชร์ทั้งไฟล์

เปิดแอปตรวจรายการจองและยอดที่ต้องชำระหลังจองสำเร็จ
หากผล timeout หรือไม่ชัดเจน ให้ตรวจรายการในแอปก่อนสั่งรันซ้ำ
รันเพียง **หนึ่ง process ต่อบัญชี** ไม่เปิดคำสั่งตั้งเวลากับคำสั่งทันทีซ้อนกัน
บอตตรวจรายการเดิมของวันนั้น และไม่จองเพิ่มเมื่อพบรายการที่ยังไม่ยกเลิก

หากพบ 401/403 อาจเป็น session หมดอายุหรือสิทธิ์บัญชี
ดู [วิธีสร้าง session ใหม่](renew-api-session.md) ปัจจุบันไม่มี login/refresh token อัตโนมัติ
หลังเปลี่ยน session แนะนำหยุดด้วย Ctrl+C แล้วเริ่มคำสั่งใหม่
